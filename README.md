## 解決什麼問題

換人是教練在比賽中最常做、也最難事後評估的決定。數據網站多半只列出球員整季成績，但臨場真正需要的是：

- **差多少**：在「這個投手、這個局數、這個比分與壘況」下，換上誰會比現任更有利？差距有多大？
- **誰接守**：代打之後守備排不排得出來？需不需要再動用一位板凳？
- **憑什麼**：估計的依據是什麼？樣本夠不夠？兩個模型的看法一致嗎？

## 主要功能

| 功能 | 說明 |
|---|---|
| **代打評估** | 設定局數、比分、壘況、出局、對方投手與輪到的打者，比較現任與最多四位板凳候選的勝率換算差距，並檢查換人後的接守安排 |
| **換投評估** | 輸入場上投手的本場球數，比較牛棚投手對上接下來三棒的差距，並納入用球數疲勞 |
| **我方場上名單** | 用球場圖和棒次表安排九棒與投手；球隊模式下，候選自動排除場上球員 |
| **2025 單日分析** | 回到 2025/09/20 的三場比賽（共 226 個打席），只用賽前資料看系統當時的建議，再依序揭示教練的實際調度與結果 |

使用方式分為「一般使用者」（直接挑人比較）、「球隊」（先套用場上名單）與「單日分析」三個入口。

## 方法

```
逐球與出賽資料 ─┬─ 部分池化模型：打者能力、左右投打、對各類球路的適性（小樣本向整體基準收縮）─┐
                └─ 梯度提升樹：沿用投手歷史投球，模擬候選打者的逐球結果並換算得分 ───────┴─ 各半整合
                                                                          → 依當下局勢換算成「勝率差距（百分點）」
```

- **比較基準**：現任固定為 0，候選的正值表示估計較有利。
- **價值分數（1–100）**：在同一比較池中的相對位置，不是成功率。
- **歷史回放不偷看未來**：能力、名單與負荷都只用比賽當天以前的資料。

## 驗證結果

我們用時間順序檢驗模型，並如實呈現結果：

- **預測誤差**：2025 年 9–10 月（5,396 打席）的得分預測誤差比聯盟基準低 0.18%，但 95% 區間跨零，**尚不能確認優於基準**。
- **換投時機**：2025 年第 6 局起的 11,868 個換投決策中，教練實際讓投手續投時，系統有提示換投的打席，進攻方 RE24 平均高 **+0.043 分**（依比賽重抽樣 95% 區間 +0.015 至 +0.069）。這是觀察性差異，不證明換投就能改善結果。
- **數值一致性**：網站顯示的數值與 Python 重算的 452 組攻守比較一致。

模型差距是估計值，實際出賽資格、傷病與當日守位仍需人工確認。

## 本機執行

需要 Python 3.10–3.11。

```bash
python -m pip install -r requirements.txt
python download_data.py      # 下載 Rebas 逐球資料與 ldkrsi 守位資料
python server.py             # 開啟 http://127.0.0.1:8000（Windows 也可雙擊「啟動系統.bat」）
```

訓練好的模型（`models/`）已隨專案提供，不需要重新訓練。
