# 當下情境球員價值評估系統（原型）

比賽中換人時機（打席與打席之間），評估「續打 vs 各代打人選」與「牛棚各投手」，
並檢查換人後守備排不排得出來。不做打席中逐球的攻擊策略。

**線上版：https://da-xiong-chen.github.io/baseball_project/**

## 兩種使用方式

| | 線上版（GitHub Pages） | 本機完整版 |
|---|---|---|
| 開啟 | 直接點上方網址 | `python server.py` → http://localhost:8000 |
| 計算 | 瀏覽器內 `docs/engine.js`（模型參數 `docs/data/model.json`） | Python 即時計算 |
| 歷史回放 | 2025 年所有實際換代打的情境（約 420 個，預先計算） | 2025 年任一打席 |

兩者結果一致（`engine.js` 與 Python 版經數值比對，差異 < 0.0001 個百分點）。

### 本機安裝

需要 Python 3.10+、pandas、numpy、scipy。

```bash
python download_data.py       # 下載 Rebas 2024–2025 逐球資料與 ldkrsi 守備資料
python server.py              # 或雙擊「啟動系統.bat」
```

2025 守位資料（`data/cpbl/positions_2025.csv`，欄位 `ID,Name,Team Name,POS,G`）由中職官網「全記錄查詢」依守備位置篩選整理，
屬中職官網內容，**不隨 repo 公開**；沒有此檔時系統只用 2022–2024 的守位紀錄。

### 更新線上版

修改模型後重新匯出，再 push：

```bash
cd src
python mlmodel.py             # 訓練梯度提升樹（全資料 + 2025 各月截止，約 20 分鐘，存在 models/，不進 repo）
python export_static.py       # 產生 docs/data/（約 15 分鐘，含逐日重建模的回放資料）
```

| 模式 | 用途 |
|---|---|
| **自訂情境・我方進攻** | 設定局數、比分、壘包、出局、對方投手、輪到的打者與板凳 → 每位人選的預估勝率、誤差、可信度、守備檢查與建議 |
| **自訂情境・我方防守** | 設定場上投手、本場已投球數、先發／後援、對手接下來 3 棒、牛棚 → 換投建議與疲勞警示 |
| **歷史回放** | 選 2025 年任一場比賽的任一打席 → 系統「當時」會怎麼建議（只用該日以前的資料），並對照實際發生的結果 |

點表格任一列可看該打者 vs 投手的 8 格球路明細（投手使用率 × 打者揮空偏離）。

## 運作方式

系統採用**集成模型**：以下兩個模型的「每打席預期得分值」各占一半。

```
① 階層式模型   = 投手 8 格球路分布 × 打者對各格的適性 + 打者本身能力 + 投手本身能力 + 左右投打（部分池化）
② 梯度提升樹模擬 = 取投手實際投過的 150 顆球（位置、球種、球速、球數），換上候選打者，
                  以梯度提升樹預測每顆球的結果機率（壞球/好球/揮空/界外/弱擊/強擊），換算成預期得分
當下價值（勝率 %）= 相對聯盟平均打者的得分值 × 此局勢「1 分值多少勝率」
```

打者／投手傾向特徵（揮空、強擊、出棒、得分值）一律先做部分池化再餵給梯度提升樹，處理替補小樣本；
訓練時以 5 折（依比賽分折）out-of-fold 估計，避免標籤洩漏。

| 檔案 | 內容 |
|---|---|
| `src/load.py` | 讀 Rebas 2024+2025 逐球資料、重建球數、計算每顆球的得分價值（加總後與官方 RE24 相關 0.996） |
| `src/model.py` | 部分池化模型；只用截止日以前的資料，可做歷史回放不偷看未來 |
| `src/roster.py` | 守位能力、當日名單推估、換人後守備檢查 |
| `src/engine.py` | 代打評估、牛棚評估（集成） |
| `src/mlmodel.py` | 梯度提升樹訓練、存檔、投手歷史球模擬 |
| `src/ml_compare.py` | 逐球結果的機器學習演算法比較 |
| `src/experiment.py` | 打席開始前評估方法的完整比較實驗 |
| `server.py` | 本機網頁伺服器與 JSON API（標準函式庫） |
| `docs/` | 前端頁面（純 HTML/CSS/JS，支援深色模式與手機版），同時是 GitHub Pages 網站 |
| `docs/engine.js` | 靜態版計算引擎（Python 邏輯的 JS 版本） |
| `src/export_static.py` | 匯出線上版所需的模型與回放資料 |

**球路格**：球種群（速球 FF/SI、滑卡 FC/SL、曲球 CU、低落 CH/FO/FS）× 高低（coordY < −21 為低球），共 8 格。

**局勢換算**：用歷史資料估計各局勢下 WPA 與 RE24 的比例（1 分值多少勝率），例如 10 局下平手二三壘 1 分 ≈ 21% 勝率，全聯盟平均約 8.6%。

## 方法比較實驗

### 1. 逐球結果預測（`ml_compare.py`；訓練至 2025/6/30，測試 2025/7/1 後 50,906 球）

| 模型 | 6 類 Log Loss | 比只看球數改善 | 準確率 | 訓練秒數 |
|---|---|---|---|---|
| 只看球數 | 1.550 | — | 36.7% | 0 |
| 邏輯斯迴歸 | 1.133 | +26.9% | 56.7% | 2 |
| 隨機森林 | 1.117 | +28.0% | 57.2% | 11 |
| **梯度提升樹** | **1.088** | **+29.8%** | **57.8%** | 16 |
| MLP 神經網路 | 1.096 | +29.3% | 57.5% | 11 |
| SVM（只能抽樣 1 萬球） | 1.152 | +25.7% | 56.3% | 37 |

梯度提升樹顯著優於隨機森林與邏輯斯迴歸（依比賽 bootstrap 95% 區間不含 0）。
特徵重要性：進壘位置 ≫ 球數 > 球種 > 打者傾向 > 球速 > 其他——**一顆球的結果主要由投到哪裡與球數決定，球員差異相對小**。

### 2. 打席開始前的評估（`experiment.py`；2025/5–10 每月月初重新訓練，預測該月）

| 方法 | 打席得分值預測改善（相對聯盟平均） | 代打第 1 名一致 | 前 3 名 |
|---|---|---|---|
| 隨機挑選 | — | 16.6% | 49.5% |
| 階層式 | +0.420% | 29.7% | 68.4% |
| 邏輯斯迴歸模擬 | +0.374% | 31.4% | 67.0% |
| 隨機森林模擬 | +0.206% | 26.6% | 62.0% |
| 梯度提升樹模擬 | +0.350% | 29.7% | 66.7% |
| MLP 模擬 | +0.333% | 30.6% | 64.6% |
| **集成（階層式＋梯度提升樹）** | **+0.472%**（95% 區間 +0.33% ~ +0.62%） | **32.1%** | **71.5%** |

集成在兩項指標都最佳，因此系統採用集成。但它相對單用階層式的改善（+0.052%，95% 區間 −0.030% ~ +0.129%）
**未達統計顯著**；單獨使用機器學習模擬並未勝過階層式模型。

## 早期驗證（階層式模型；2025/6–9 每月滾動）

| 檢驗 | 結果 |
|---|---|
| 打席得分值預測 | 完整模型比聯盟平均改善 0.41%（95% 區間 +0.19% ~ +0.64%）；**不池化的打者原始平均反而比聯盟平均差** |
| 球路適性對得分預測的額外貢獻 | 不顯著（95% 區間 −0.04% ~ +0.09%） |
| 球路適性對**揮空**預測 | 顯著改善 0.91%（95% 區間 +0.65% ~ +1.19%） |
| 與教練實際代打選擇比較（421 次） | 第 1 名一致 29.7%（隨機 16.6%）；前 3 名 68.2%（隨機 49.5%）；高張力情境前 3 名 72.8% |

單一打席結果的隨機性極高，改善幅度小是正常現象（大聯盟研究也是如此）。

## 重要發現

1. **打者 × 球種的「得分」差異，用逐球得分值偵測不到**：雜訊太大，部分池化會把它縮到 0。
   改用穩定得快的成分後，**揮空率**有明確的球路適性訊號（約 160 球就有一半可信度），
   **強勁擊球率**也有，但需要約 800 球。
2. 目前分數主要由**打者整體能力**和**左右投打**決定，球路適性的影響約為每打席 ±0.005 分。
3. 代打的勝率差異通常在 1% 以內；只有高張力局面（延長賽、九局接近比分）才會拉大。

## 已知限制

- **2025 守位資料是整季累計**，歷史回放時會用到「未來」的守位紀錄（例如某人 8 月才開始守游擊）。正式版應改用逐場守位或只用前一季。
- **當日名單是推估的**：過去 10 天出賽過的野手。實際使用時應由教練勾選。
- **守位分配是推估的**：依出賽紀錄最大化指派 9 人守位，不是實際當天守位。
- 守備只判斷「能不能守」，沒有守備好壞的數據。
- 換投評估只看接下來 3 棒，沒有考慮投手後續可用局數。
- **用球數疲勞**（`src/fatigue.py`）：由 2024–2025 先發投手資料估計，85 球以前不調整，95 球約每打席 +0.027 分、105 球約 +0.047 分，之後線性外推（上限 +0.12）。因教練只讓狀況好的先發投長局（倖存者偏差），實際疲勞可能被低估。後援投手 30 球以上樣本太少，只警示不調整。歷史回放會自動從資料算出當下用球數。
- 跑壘（代跑）尚未納入。
