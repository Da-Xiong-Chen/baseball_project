### 本次功能更新

- 功能選單分為「換打／換投評估」、「我方場上名單」與「2025 單日分析」。一般使用者直接進入評估，可自由選球員；球隊模式先套用九棒、守位及投手，現任依場上配置，板凳／牛棚候選排除場上人員。名單支援姓名／2025 背號搜尋、球場圖及棒次互換。
- 名單頁可配置九棒、守位與投手，也可人工標記已退場／今日不可用球員，套用後排除候選。只在此瀏覽器保存，不是官方今日先發或跨裝置同步；不自動追蹤退場、DH 存續或完整換人資格。初版支援一般 DH 配置，特殊 DH／投打雙向安排不在本次範圍。
- 名單頁預設帶入各隊 2025 最後 30 場的先發陣容：捕手取最常先發者；其餘守位只排有守過該位置（≥ 3 場，與守備檢查相同）的球員，在此前提下取先發次數最多者（平手比全季先發），沒有守位的主力排指定打擊；棒次依平均先發棒次，投手取最常先發者（`scripts/export_default_lineups.py` → `docs/data/default-lineups-2025.json`）。此瀏覽器已有保存配置時以保存為準；可按「恢復預設名單」。防守評估的「對手接下來三棒」也預設為對手預設名單第 1–3 棒。
- 「2025 單日分析」含 2025/09/20 六隊三場總覽、逐打席回放、賽前近期配球與負荷狀態，以及模型驗證頁。依時間並排看系統提示與實際調度，可點分類下鑽，再分次揭示實際調度與結果。歷史不受一般／球隊模式、當前名單或手動不可用清單影響。
- 修正：套用名單中的場上投手時，「先發／後援」與預設球數沒有同步，畫面顯示後援、實際卻以先發評估。名單狀態在有未套用修改時另外標示。
- 效能：對戰估計改用查詢表（結果與原本逐位相同，速度約 10 倍），換投評估不再重複呼叫梯度提升樹。

- 頁首可選深色／淺色，首次預設淺色，記住同瀏覽器的選擇；已選深色者繼續使用深色。切換不清除情境或改變推薦。
- 「現任與候選比較」以現任為固定基準，兩種評估皆可用姓名前的圓圈選擇最多四位候選；選第五位時移除最早選取者。圖表以綠／紅呈現相對優劣；姓名連至 CPBL 官方資料，圓圈同步切換本站對決明細。
- 換投明細列出後續每位打者的估計及疲勞項，與合計失分價值對照；這是得分期望變化的價值，可為負值，不是實際會失幾分。僅比較接下來最多三棒，不是整場換投最適策略。
- 勝率換算使用「百分點」，價值分數是比較池百分位；原「可信度」在介面標為樣本充分度，不當成排名把握度。
- 歷史估計的慣用手、守位、比較池、疲勞曲線與逐球得分期望表均限制在截止日前。可用名單仍由過去出賽推估，不能冒充官方當日登錄或健康資訊。

目前本機 v4 已驗證 18 組自訂情境，Python／JS 數值最大差約 0.000013；275 場、498 個一般代打回放與固定日 226 打席／452 組攻守比較通過。同名林子崴以原始球員 ID 區分。2026-10-23前端170項、Python88項及最終452個HTTP回放視圖通過；另實際操作桌面與390px手機寬度下的主要流程。公開站v4基礎版本已確認，本輪兩項顯示修訂仍須經新PR審查與部署。

**模型採用決策：**維持現行階層式／GBT 各半集成。新增聯合比賽重抽樣完成兩組種子、共 3,200 次，區間與提示門檻的跨種子判定仍有變動，已決定不採用新區間，不再加算。現有細線僅為階層式近似誤差，不是完整集成區間、候選勝出機率或換人收益保證。

### 本機安裝

v4 權重沿用 Python 3.11.4、numpy 1.24.3、scikit-learn 1.3.0 建立；依賴固定於 `requirements.txt`。pickle 不保證跨 sklearn 版本相容。缺少 v4 權重會指出訓練指令，不會在開啟網站時自動重訓。舊演算法比較另需 `pip install xgboost lightgbm`。

```bash
python -m pip install -r requirements.txt
python download_data.py       # 下載 Rebas 2024–2025 逐球資料與 ldkrsi 守備資料
python server.py              # 或雙擊「啟動系統.bat」
```

2025 守位資料（`data/cpbl/positions_2025.csv`，欄位 `ID,Name,Team Name,POS,G`）由中職官網「全記錄查詢」依守備位置篩選整理，
隨 repo 提供，著作權屬中華職棒、僅供本競賽分析使用（來源見 [資料來源.md](資料來源.md)）；沒有此檔時使用可取得的 2023–2024 守位紀錄。歷史回放不使用當季整季守位；缺少守位紀錄時不能當成已確認可守。守位是經驗門檻與分配推估，不是實際當場守位或守備品質。

啟動 `http://127.0.0.1:8011/`（PowerShell）：

```powershell
$env:PORT = '8011'
python server.py
```

伺服器只綁定本機。主題偏好儲存被瀏覽器禁止時，當次仍可切換。模型缺少慣用手時會顯示估計假設與資料有限提示，不能將其當成可靠的左右優勢。

| 模式 | 用途 |
|---|---|
| **自訂情境・我方進攻** | 設定局數、比分、壘包、出局、對方投手、輪到的打者與板凳 → 每位人選的預估勝率、誤差、可信度、守備檢查與建議 |
| **自訂情境・我方防守** | 設定場上投手、本場已投球數、先發／後援、對手接下來 3 棒、牛棚 → 換投建議與疲勞警示 |
| **歷史回放** | 選 2025 年任一場比賽的任一打席 → 系統「當時」會怎麼建議（只用該日以前的資料），並對照實際發生的結果 |

**價值分數（1–100）**：對決估計在截止日前比較池的百分位。打者門檻是該季累積 100 打席，後援門檻是 15 場；早季沒有合格球員時回退前一季，無比較池時不給分。人數會隨截止日改變。
50 約為比較池中位位置，不是聯盟平均能力或成功率。換投分數的方向已調整為失分價值越低越佳。
分數只反映對戰適合度；局面關鍵程度由「預估勝率」呈現。80+ 極佳、60–79 佳、40–59 普通、20–39 不利、<20 很不利。

點表格任一列可看該打者 vs 投手的 8 格球路明細（投手使用率 × 打者揮空偏離）。

## 近期配球比較

評估完成後，按「查看配球比較」，比較目前所選投手最近5場與之前最多10場。
點選候選打者／牛棚投手時，比較會跟著對決切換。可切換實際左打、右打或合計。

「同條件比較」依球數與左右打校正，呈現百分點差與探索性區間。樣本不足時，預設改看「觀察配球（未調整）」的實際比例與球數，並明示不足原因；原始視角不產生調整後區間或趨勢結論，嚴格判定門檻不變。兩種視角均不改推薦分數。
歷史回放只納入比賽日期之前的出賽；自訂情境仍是 2025 資料的展示，不是 2026 即時資訊。

從專案根目錄執行：

## 新增：換人時機比對

`src/timing_backtest.py` 收錄 2025 例行賽第 6 局起的 11,962 個決策點，本輪全部重算成功。其中換投有效 11,868 個、無牛棚候選 94 個；代打有效 9,038 個、守位未確認 2,813 個、無板凳 111 個。不能評估者不放入「未建議換人」分母。
算法、名單推估與截止日都與「逐打席回放」相同（集成模型＋用球數疲勞，只用比賽當天以前的資料）：

- 換投：上一打席的投手續投 vs 推估可用牛棚，對上接下來 3 棒；代打：輪到的打者 vs 推估板凳。守位只接受確認可接守的人選；候選皆未確認時列為不可評估。
- 最佳候選的勝率換算差值 ≥ 1 百分點視為「系統建議」。全季研究統計保留在匯出 JSON 與本節；網站集中呈現 2025/09/20 單日。逐打席列表的外框標籤「系統：換投／代打」表示系統建議，實心標籤「換投／代打」表示實際調度；點選後可分別查看攻守比較及時機比對。單日不沿用全季顯著性結論。
- 現任打者：不是代打的打席以實際打者為現任（含守備替補上場、尚未打過的球員）。
- 驗證：系統建議換、但實際沒換的打席，留在場上的人該打席 RE24 是否比系統不建議時差。

| 門檻 | 換投：實際／系統建議／同一打席都換 | 續投時 RE24 差（95% 區間） | 代打：實際／系統建議／同一打席都換 | 原打者上場時 RE24 差（95% 區間） |
|---|---|---|---|---|
| 0.5 | 2,184／4,552／955 | +0.019（−0.001 ~ +0.040） | 400／1,038／97 | +0.007（−0.022 ~ +0.036） |
| **1.0** | 2,184／2,541／592 | **+0.043（+0.015 ~ +0.069）** | 400／228／32 | −0.021（−0.071 ~ +0.030） |
| 2.0 | 2,184／820／220 | +0.016（−0.022 ~ +0.057） | 400／4／2 | 樣本不足，無可靠區間 |

以上為依比賽重抽樣 2,000 次的 95% 區間（種子 20261020），不是獨立打席常態區間。門檻 1 時，實際續投且系統建議換投的 1,949 打席，RE24 平均比未建議組 7,735 打席高約 0.043。這是觀察性風險差異，未排除教練選擇、球隊與局勢組成，不證明換投後能改善。換投評分看最多三棒，此處診斷僅觀察一打席，不能稱為整段策略驗證。

六局起有 2,204 次實際換投，20 次缺少可分類的估計；其餘 2,184 次中，167 次同一打席首次提示、667 次在觀測窗內較早提示（中位數 3 打席）、1,350 次在目前可觀測窗內未提示。708 次換投的原登板段始於六局前；不能稱為整段登板從未提示。完整原始登板 ID 先建好再切六局研究窗，缺估計不跨段拼接。

限制：可用名單與守位由此前出賽推估，不含傷病與登錄；缺守位不等於確定不能守。球隊、月份、局數帶、比分帶與先發／後援另做描述性共同支持檢查，只報支持範圍，不宣稱消除混雜或提供因果效益。
`python tests/verify_timing.py` 會抽樣核對時機資料與回放頁的計算一致。

## 近期加權回測（未啟用）

`src/recency_backtest.py` 測試資料權重隨時間衰減（半衰期，天數不含休季）是否能更準地預測下個月（2024/6–9、2025/5–9 共 9 個月，數字為每萬球降低的平方誤差，相對不加權）：

| 半衰期 | 投手 | 95% 區間 | 打者 | 95% 區間 |
|---|---|---|---|---|
| 90 天 | +0.008 | −0.050 ~ +0.067 | −0.038 | −0.087 ~ +0.010 |
| 180 天 | +0.018 | −0.024 ~ +0.059 | −0.019 | −0.044 ~ +0.007 |
| 365 天 | +0.016 | −0.009 ~ +0.042 | −0.000 | −0.013 ~ +0.012 |

投手的改善很小且區間含 0，打者持平或變差，因此 `model.PITCHER_HALF_LIFE` 預設為 `None`（不加權，模型輸出與原本相同）。資料增加後可重跑再決定。
連續出賽的疲勞同樣檢查過：後援連續日登板、先發休息天數、打者 7 天內出賽數，都沒有可測到的表現差異（教練不會派明顯疲勞的人上場），因此沒有加入跨日疲勞扣分。

## 運作方式

系統採用**集成模型**：以下兩個模型的「每打席預期得分值」各占一半。

```
① 階層式模型   = 投手 8 格球路分布 × 打者對各格的適性 + 打者本身能力 + 投手本身能力 + 左右投打（部分池化）
② 梯度提升樹模擬 = 取投手實際投過的 150 顆球（位置、球種、球速、球數），換上候選打者，
                  以梯度提升樹預測每顆球的結果機率（壞球/好球/揮空/界外/弱擊/強擊），換算成預期得分
當下價值（勝率 %）= 相對聯盟平均打者的得分值 × 此局勢「1 分值多少勝率」
```

打者／投手傾向特徵（揮空、強擊、出棒、得分值）一律先做部分池化再餵給梯度提升樹，處理替補小樣本；
訓練中的球員傾向特徵以 5 折（依比賽分折）out-of-fold 估計，降低同場結果直接進入特徵的洩漏；歷史訓練標籤另外按截止日前資料重建。這不等於所有分布偏差或反事實問題都已解決。

| 檔案 | 內容 |
|---|---|
| `src/load.py` | 讀 Rebas 2024+2025 逐球資料、重建球數、計算每顆球的得分價值（加總後與官方 RE24 相關 0.996） |
| `src/model.py` | 部分池化模型；只用截止日以前的資料，可做歷史回放不偷看未來 |
| `src/roster.py` | 守位能力、當日名單推估、換人後守備檢查 |
| `src/engine.py` | 代打評估、牛棚評估（集成） |
| `src/mlmodel.py` | 梯度提升樹訓練、存檔、投手歷史球模擬 |
| `src/ml_compare.py` | 逐球結果的機器學習演算法比較（含 XGBoost、LightGBM） |
| `src/experiment.py` | 打席開始前評估方法的完整比較實驗 |
| `server.py` | 本機網頁伺服器與 JSON API（標準函式庫） |

**球路格**：球種群（速球 FF/SI、滑卡 FC/SL、曲球 CU、低落 CH/FO/FS）× 高低（coordY < −21 為低球），共 8 格。

**局勢換算**：用歷史資料估計各局勢下 WPA 與 RE24 的比例（1 分值多少勝率），例如 10 局下平手二三壘 1 分 ≈ 21% 勝率，全聯盟平均約 8.6%。

## 研究依據與方法實作

### 前端圖表與分數的技術解讀

操作頁僅保留評估方式、資料範圍、圖表限制與使用限制，技術細節集中於此。下列是目前實作的解讀方式，不是新增研究成果。

- **模型與權重**：階層式模型與逐球模型的得分值依集成權重結合；目前配置通常各占一半，靜態端實際使用匯出資料的 `ml.w`。逐球估計不可用時回退階層式，不能宣稱所有歷史快照都用了完整集成。實作見 `src/engine.py`、`docs/engine.js`。
- **圖表拆解**：攻守共用「現任固定為 0」的差值圖，右側綠色表示較有利，左側紅色表示較不利。換打分項顯示候選減現任；換投逐棒圖顯示現任減候選的失分價值，含疲勞調整。原始雙方数值可展開核對。換打分項只解釋階層式部分，不能加總後直接當成完整集成的勝率差；失分價值是得分期望變化，可為負值，不是實際失分數。
- **誤差細線**：評估表細線來自階層式估計的近似標準誤，再按局勢斜率換算。它不是完整集成的預測區間，也不是候選勝出機率或排名把握度。不可由兩條細線是否重疊直接認定換人效果。
- **比較池與價值分數**：比較池由截止日前資料建立，早季不足時依既有程式回退前一季。打者依打席量，後援依登板場次與先發比例條件選入；詳細條件以 `src/roster.py` 的 `hitter_pool()`、`reliever_pool()` 為準。價值分數是池內相對百分位，同值採中間名次，映射到 1–100；它不是成功機率，也不能跨不同對決當成絕對能力。樣本資格條件不是已驗證的可靠度界線。
- **時間與資格限制**：模型與逐球資料截止日不一定相同，皆排除截止日當天。歷史守位採截止日前完整球季紀錄；實際當日守位、登錄、退場與 DH 存續需人工確認。候選比較不構成完整換人規則檢查。

## 方法比較實驗（既有版本結果）

本輪 v4 回溯式滾動比較見 `output/revision-20261021/model-evaluation.json`：5–8 月 16,981 打席／222 場做描述性設定比較，9–10 月 5,396 打席／72 場只做時間檢查。各半集成後段 MSE 0.225591、聯盟基準 0.225998；比賽重抽樣的誤差改善區間 [-0.000425, 0.001215] 跨零，尚不足支持優於基準。此次只修正校正，不重新選參數；開發期選出的最佳候選與同一開發期區間只能作描述，不能當成獨立驗證。資料曾被歷史研究看過，不稱為全新未見測試。校正前後完整模擬器欄位一致，候選差值的共同位移抵消，因此保留原全季時機計算；22,377 筆絕對預測與評估指標已依新校正重算，證明及來源雜湊見 `calibration-impact.json`。

以下保留早期版本實驗紀錄，**不能作為現行 v4 已驗證提升的證據**；教練一致率亦不是換人準確率。本輪比較未重跑早期所有演算法組合。

## 早期研究發現（歷史紀錄，非現行版本結論）

1. **打者 × 球種的「得分」差異，用逐球得分值偵測不到**：雜訊太大，部分池化會把它縮到 0。
   改用穩定得快的成分後，**揮空率**有明確的球路適性訊號（約 160 球就有一半可信度），
   **強勁擊球率**也有，但需要約 800 球。
2. 目前分數主要由**打者整體能力**和**左右投打**決定，球路適性的影響約為每打席 ±0.005 分。
3. 代打的勝率差異通常在 1% 以內；只有高張力局面（延長賽、九局接近比分）才會拉大。

- **歷史守位採前一季以前的完整紀錄**，避免當季整季資料洩漏；仍可能漏掉當季新學會的守位。當場守位與可用名單需人工確認，不是官方登錄的重現。

- **守位分配是推估的**：依出賽紀錄最大化指派 9 人守位，不是實際當天守位。

- **用球數疲勞**（`src/fatigue.py`）：以截止日前先發資料估計曲線，85 球以前不調整，之後估計值會隨截止日改變，調整上限每打席 +0.12 分。因教練只讓狀況好的先發投長局（倖存者偏差），不能將曲線當成疲勞的因果效果。後援投手 30 球以上樣本太少，只警示不調整。歷史回放會由逐球紀錄計算當下用球數。
- 跑壘（代跑）尚未納入。

## 使用方式與單日歷史分析（2026-10-13 更新）

一般使用者可直接評估，也可另存場上配置；選人仍不限於配置名單。球隊模式必須先套用有效九棒、守位與投手，現任依配置，換人候選排除場上人員。切換模式不刪除配置。

前端歷史分析聚焦 2025-09-20（星期六），六隊三場：G340 樂天／統一、G341 台鋼／富邦、G342 味全／中信。官方紀錄：https://www.cpbl.com.tw/box?gameSno=340&kindCode=A&year=2025 （場號 341、342 同日期）。當日總覽取實際代打次數及已匯出的 6 局以後系統標記，不沿用全季顯著性結論；近期配球只取當日以前快照。全季匯出檔留存供研究重現，但不再作為頁面總覽。近況權重不再出現在一般評估設定；原引擎、模型檔及全季研究結果不變。

網站仍使用 2024–2025 模型與球員資料，不是 2026 即時球員能力或登錄名單。線上版已收錄當日全部 226 個打席的完整比較，點選時只載入該打席資料。能力估計截止於 2025/09/20 賽前，逐球模型截止於 9/1，不以全季模型補缺。19 次實際換投另保留原投手續投的比較版本；代打則面對該打席的實際投手。

兩種使用模式皆可進入評估與場上名單；單日分析是獨立功能，不顯示使用模式選擇，也不讀取當前場上配置。單日換隊與一般評估的球隊選擇互不影響。

完整單日快照可由 `python scripts/export_history_day.py` 重新產生；此腳本要求已有相容月初模型，不會自行訓練。`python tests/verify_history_day.py` 會重算 452 組攻守結果，核對全部快照與 184 組時機標記。本次驗收見 [單日回放與使用流程驗收](docs/qa/day-release-20261019/README.md)。

### 賽季中狀態回溯

2025/09/20 歷史頁增加投手／打者狀態卡，可選球員查看賽前連續出賽天數、完整休息天數、近三天球數／打席、近14天出賽與負荷紀錄，以及三振、保送或安打樣本。投手可輸入模擬本場球數與角色，顯示以截止日前資料估計的先發球數疲勞值；後援30球以上只警示，連投天數不自動換算扣分。這是賽前狀態重建與負荷情境，不是任意歷史投打組合的完整模型重算；評估仍沿用原匯出打席。生成方式：`python scripts/export_history_context.py`，原始資料不公開，只輸出衍生摘要。一般模式打者選單先列已套用九棒，再列其他球員；球數輸入仍保留於換投評估。

「我的預設・進階設定」僅在2025歷史情境頁顯示，保存球隊、球員、換投／換打、模擬球數及角色，連投疲勞強度僅作歷史狀態情境假設。當下評估不讀取歷史近況與連投疲勞偏好，仍保留實際本場球數與原用球數疲勞估計。

## 靜態發布前檢查

僅修改前端時不必重新訓練或匯出模型。先執行前端、Python 測試與 `python scripts/prepare_site.py`；再以桌機／手機寬度操作兩種評估、群組保存、場上名單與回放。外部資料連結的授權仍以來源條款及專案取得的許可為準，檢查程式不會替代授權確認。

如需交給其他靜態主機，可建立乾淨發布資料夾：

```bash
python scripts/prepare_site.py --output output/site-release
python -m http.server 8032 --directory output --bind 127.0.0.1
```

開啟 `http://127.0.0.1:8032/site-release/`，以子路徑檢查資源載入。發布資料夾只含入口引用的前端檔、授權副本與匯出 JSON，附 SHA-256 清單；不包含 QA 圖片、原始 CSV、pickle 模型或開發報告。程式拒絕覆寫既有資料夾，重建時請換新名稱。這是本機準備動作，不會上傳。

GitHub Pages 若仍設定 `main /docs`，發布內容依協作流程合併及部署；不能用本機預覽取代部署後驗收。`server.py` 是本機完整版，不是公開 API 代管方案。正式對外上架前，專案負責人仍須確認 2025 CPBL 守位資料的使用範圍（目前資料來源文件記為「僅供本競賽分析」），以及程式碼授權與實體裝置驗收。本輪沒有擅自替專案新增授權或變更資料。
