### 跨年度球員 ID 連續資料層

新增 `scripts/build_identity_continuity.py`，將原始 box-score `playerId` 保存為來源命名鍵 `rebas:CPBL:<playerId>`，建立獨立 SQLite 資料庫。建置採新目錄、暫存資料夾、完整性檢查後原子發布；目的地已存在時拒絕覆寫。原始逐場 JSON 唯讀，資料庫以檔案相對路徑與 SHA-256 留存來源追溯。

本機產物：`output/player-identity-20261025-v2/identity.sqlite`、`identity-review.json`、`manifest.json`、`README.md`。目前建置包含 2024–2025 共 720 場、415 個來源 ID、22,630 筆 box-score 觀測、54,885 打席與 206,108 顆逐球；SQLite 完整性檢查為 `ok`，外鍵違規為 0。打者、投手及捕手僅在同場同隊 box-score 內按精確姓名唯一對應，未解析者列入問題表；本次打席與逐球均為 0 筆未解析身份。

完整掃描發現逐球事件與打席摘要有 100 筆參與者名稱差異：打者 18、投手 56、捕手 26。v2 逐球採事件自身的名稱解析 ID，並保存差異明細；僅事件未提供該欄位時才明確標記沿用打席姓名，事件明示空值不補值。逐球統計也直接按逐球 ID 計數，不再沿用打席摘要的身份。這是本資料層的修正，正式載入器的接入及重訓仍屬後續整合工作。

資料層確認 1 組同名不同 ID（林子崴：`gdEku`、`yhCr`）維持分離，另保留 6 組同 ID 多名稱、263 個跨年度 ID，以及 17 個觀測到多隊名稱的 ID。名稱與球隊都不建立全域「最新值」，跨隊觀測也不等同已驗證的轉隊日期。以 `--as-of` 查詢時，只統計截止日當天及之前的 box、打席與逐球；例如 `8llux` 在 2025-05-22 的查詢不會出現 2025-05-23 才觀測到的名稱，截止日移到 2025-05-23 才會列入。查詢以日期為粒度，不代表同日比賽當下已知的即時名單。未知 ID 與尚未出現的 ID 都只回報截止日前未有觀測，避免透露未來存在性。

新增獨立核對器 `scripts/verify_identity_continuity.py`：直接從全部原始 JSON 重建期望值，逐筆比對出場、打席、逐球、來源雜湊及名稱／球隊歷程，不只比較總數；再對全部 415 個 ID 的名稱與球隊首次觀測日前後、跨年及資料末日執行 2,532 組歷史查詢。驗收 0 項失敗；另一份完整重建的資料庫、報告、README 與 manifest 四個檔案雜湊完全一致。證據保存於 `output/player-identity-verification-20261025/full-source-verification.json`。

四筆原始球速異常仍保留原始 JSON 值，未插補或改寫。這個資料層是身份／時間追溯基礎，不表示球員資料、守位資格或模型已完成驗證，也沒有接入正式網站、正式模型或簡報。執行範例見產物 `README.md`。

### 第 29 頁：長短期權重的可重現比較報告

新增 `scripts/report_recency_experiment.py`，沿用既有 `src/recency_backtest.py` 的時間切分與階層式球員整體效果：2024/06–09、2025/05–09 共九個月，每月只用月初以前的資料建模，再評估該月觀察值。比較不衰減基準與 90、180、365 天半衰期，保存逐月結果、程式及原始資料雜湊、固定種子與進度。既有報告不覆寫。

推論以比賽成對重抽樣 2,000 次，同一次抽樣的分母也改用抽到的逐球數，避免大小不同的比賽被套固定分母。共 507 場、145,112 顆有效評估球。

指標是「相對同一不衰減階層式基準，每萬球減少的平方誤差」，正值較好，**不是勝率百分點或實際換人收益**：

| 效果 | 半衰期 | 相對改善 | 探索性 95% 區間 |
|---|---:|---:|---|
| 投手 | 90 天 | +0.00731 | −0.04904～+0.06818 |
| 投手 | 180 天 | +0.01797 | −0.02050～+0.06133 |
| 投手 | 365 天 | +0.01553 | −0.00934～+0.04129 |
| 打者 | 90 天 | −0.03771 | −0.08409～+0.00981 |
| 打者 | 180 天 | −0.01850 | −0.04393～+0.00789 |
| 打者 | 365 天 | −0.00003 | −0.01196～+0.01256 |

六組區間均包含 0，因此維持原設定 `PITCHER_HALF_LIFE=None`，不因選到一組較好的平均值就更新網站。九個月份用來比較多個候選，沒有額外未碰過的選模後測試集；區間是探索性結果。這次只完成階層式整體效果的比較工具與實驗，**未完成完整集成模型與候選排名穩定性驗收**，不能把第 29 頁的全部規劃標成完成。

執行：

```powershell
python scripts/report_recency_experiment.py --out output/recency-run/report.json --seed 20261025 --resamples 2000
```

本輪結果：`output/future-work-20261025/season-intake.json` 與 `recency-experiment.json`。原始資料保存在本機，不隨程式上傳。報告以相對路徑與雜湊描述輸入。
