## 結論與範圍

PR #26 的既有回測範圍為「2025/09/20 六隊三場單日分析＋模型時間驗證」。本輪修正三個可重現的錯誤恢復／非同步問題後，未發現仍會阻擋這個範圍操作的核心功能缺漏；不需要為初稿展示再增加分析頁、重訓模型或擴充新功能。

**公開網站尚未同步，因此不能簽認公開新版已可用。** 2026-10-22 22:01（Asia/Taipei）唯讀請求顯示：首頁正常回應，但 `data/model.json` 仍為訓練版本 2；`backtest.js`、`data/model-evaluation.json` 回 404。當日索引雖有 226 打席，亦與本機 v4 不同。這代表公開站仍提供舊版，不能把舊版首頁能開啟視為新版回測驗收通過。詳見 `public-version.json`。

## 本輪找到並修正的問題

1. **模型驗證的重試未重新抓取資料。** HTTP 成功但 JSON 格式不完整時，原先仍將內容留在記憶體快取；即使檔案已修正，按重新載入也會一直失敗。現在驗證載入會明確重新請求。
2. **系統建議標記的重試有相同問題。** 現在重新載入建議會重抓時機資料；同時保留標記無法載入時仍可查看實際紀錄的降級方式。
3. **較舊的驗證回應可能覆蓋最新狀態。** 加入每個驗證容器的請求識別，過期成功與失敗均不覆蓋最新畫面；舊 JSON 請求失敗也不會刪掉較新的成功快取。

三項問題皆先以回歸測試重現，再修正。網站腳本網址已更新，讓重新進站的瀏覽器取得相同版本。

## 重跑方式

在專案根目錄執行；Node 與 Python 需使用專案相容版本及依賴。

```sh
node --test tests/*.cjs
python -m unittest discover -s tests
python scripts/prepare_site.py
python scripts/closeout_batch.py --verify-live
```

已啟動相同網站檔案的本機服務時，可令 `BASEBALL_QA_BASE_URL=http://127.0.0.1:連接埠/`，再執行 `node --test --test-name-pattern="all 226 fixed-day" tests/test_app_state.cjs`，以真實 HTTP 來源重跑全日應用流程。另以 `python tests/qa_http.py http://127.0.0.1:連接埠` 驗證 API。
