# 11/14 前端改用 2026 球季資料

網站的自訂評估、球隊名單、背號搜尋與預設先發，改用 2026 球季。模型沿用 v5 方法（階層式部分池化與梯度提升樹各半），訓練資料改為 2024–2026 三季例行賽，截止日 2027-01-01（不含）。2026/10/04 單日回放沿用原本的賽前批次，未變動。

## 資料進件

- 來源：Rebas Open Data。2024、2025 沿用 v5 訓練用的 v0.1.0；2026 為 [v0.1.1-2026](https://github.com/rebas-tw/rebas.tw-open-data/releases/tag/v0.1.1-2026) 例行賽。
- 以 `scripts/stage_season_update.py` 建立隔離資料集：三季共 1,080 場，新增 2026 的 360 場，既有 720 場原樣保留，沒有更正檔。[進件摘要](intake.json)
- 原始量測例外 6 筆皆為無法解讀的球速（2024 兩筆、2025 兩筆、2026 一場兩筆），原值保存，載入時視為缺值。
- 2026 守位：由 Rebas 2026 每個打席的守備陣容快照整理，360 場、27,268 個打席全部解析，共 515 筆球員／球隊／守位。[守位收據](fielding-2026.json)

## 守位判斷

截止日在 2026 季後時，守位紀錄依序為 2026 實際守位（權重 1）、2025 中職官網（0.7）、2024 ldkrsi（0.4）；2026 以前的截止日維持原本設定，不影響既有批次。某守位加權出賽達 3 場以上才算能守，與原規則相同。

## 模型與匯出

- 訓練樣本 299,492 球（2024-03-30 至 2026-10-06），校準期間 2026-09-25 至 2026-10-06。批次 `ce4f4627…`，以 `scripts/stage_2026_full_model.py` 封存權重並匯出 `model.json`。[收據](receipt.json)
- 6 隊名單、181 位打者與 174 位投手的對決格完整。
- 同批次匯出 `player-numbers-2026.json`（355 人，無排除）、`default-lineups-2026.json`（各隊 2026 最後 30 場先發）與 `cpbl-players.json`。前端不再載入 2025 背號與預設名單。

## 驗收

- Python 引擎與網站 JavaScript 引擎以 54 個情境核對 1,962 個數值，最大差 1.0×10⁻¹⁴。[同情境核對](parity.json)
- 2026 預設先發名單通過守位、捕手與 DH 規則測試；前端測試與 CI（無原始資料模式）通過。
- 瀏覽器實測桌面 1280px 與手機 390px：示範情境、球隊名單、當日總覽與逐打席回放。

## 限制

- 2026 已用於模型訓練，沒有未參與的留出樣本可證明預測較 v5（2024–2025）更準。這次更新是讓前端反映 2026 球員與表現，不是宣稱模型改善。
- 本機 API 版（`server.py`、`models/active-batch.json`）仍是原 v5 批次，這次只更新 GitHub Pages 使用的靜態資料。
- 示範情境（8 局上統一 1:2 富邦）改用 2026 資料後，最佳候選陳鏞基 +0.92 百分點，未達 1 個百分點提示門檻，畫面結論為續用林佳緯。
