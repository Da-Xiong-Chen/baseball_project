# 11/06 發布驗收與程式碼審查

整合基準為主分支 be6f3b4 與 PR #33 合併提交 86d746c。合併只在簡報索引發生衝突，已保留主分支 archive 目錄與原交件，再接上 10/26 的 32 頁工作稿。原簡報及九個正式權重的內容沿用既有版本。

## 網站與審查

- 牛棚接續可選擇比較方案 B。兩案共用目標打席、投手狀態及容量，各自設定順位。結果顯示已覆蓋、缺口、使用順序與保留投手。工作表變更會清除兩案結果，換隊或換場上投手後須重新帶入。
- 審查涵蓋這次發布相對主分支的變更，包括一般／球隊入口、靜態與 API 契約、回放截止日與快取、增量進件、訓練來源與 checkpoint、匯出批次，以及 CI、文件和簡報索引。另檢視容量輸入、HTML 跳脫、退場／重複順位、狀態撤回及鍵盤焦點。
- 發現 API 自訂情境可接受歷史日期但仍使用現行模型，造成時間語意與靜態版不一致。現已統一鎖定模型截止日，舊日期請求會被拒絕，並新增 API 與 JavaScript 回歸。整合及本輪修正的數值驗收以[同情境核對](numeric-parity.json)為準，18 情境、275 場 498 筆回放通過。
- 2025 規則原型僅用於離線核對。包含先發首名打者、後援首名打者或該半局結束、局首熱身義務、經主審認定的傷病例外、已退場再進場及未知資料。依據 [CPBL 2025 棒球規則 §5.10](https://www.cpbl.com.tw/files/file_pool/1/0p065549820043528193/2025%E6%A3%92%E7%90%83%E8%A6%8F%E5%89%87%28%E5%AE%98%E7%B6%B2%E7%94%A8%29.pdf)。容量表的數字由使用者輸入，完整換投合法性與多局失分／勝率仍需獨立驗證。

## 瀏覽器操作

- 純靜態版操作一般使用者代打、換投、球隊名單九棒套用與重新整理、Esc 取消，以及樂天對統一的獨立單日回放，依序揭示實際調度和結果。API 版另走完代打、換投及開啟當日打席清單。
- 在牛棚比較中，兩位現有投手輸入測試容量 6 與 3。方案 A 覆蓋 6/6，方案 B 尚缺 3 並保留 A 的投手。另測未填容量、退場、重複順位、改名單撤回結果、清空後停用，及錯誤欄位的鍵盤焦點。
- 比較結果在 320、390、1024、1440 px 瀏覽器視窗皆未橫向溢出。桌面窄欄和手機均實際採用上下堆疊。已驗證鍵盤操作，視窗測試使用電腦瀏覽器。[牛棚比較畫面](bullpen-comparison.jpg)
- 使用本機故障站注入模型／回放 503 和 1 秒延遲。重試成功，連續切隊保留最後選擇。儲存受限的 iframe 能恢復並套用當次名單、顯示無法保存，Esc 正常關閉選人，評估仍可完成。

## 資料與模型

跨年進件用 720 場原始資料的隔離副本演練。辨識新增 1、更正 1、重複相同 1、保留 717。更正是刻意改變副本排版的情境，JSON 值相同。未授權更正、重複賽事及無法對應的事件投手均被拒絕。重建後獨立核對 415 位球員、2,532 次歷史查詢，零失敗。原檔 720 份 SHA 一致，既有四筆量測例外原樣保存。[進件](intake.json) · [身分核對](identity.json)

逐月離線近況回測覆蓋 2025 年八個月份、360 場與 27,285 打席。每個月用月初模型，固定樹模型與各半集成。比較六種投打權重、誤差、分箱校準、候選排序及單場敏感度。基準 MSE 0.240962，打者 365 天候選差約 −0.000008，兩組按比賽重抽樣的多重比較調整區間均跨零，也低於預定 0.0005 的最小改善幅度。現行權重保留，獨立新樣本仍是採用條件。[回測摘要](recency.json)
