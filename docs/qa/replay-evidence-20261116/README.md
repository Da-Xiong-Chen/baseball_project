# 2026 候選覆蓋、代打接守與新球季進件

網站的單日分析可以依日期或情境進入八個比賽日。展開「揭示實際調度」後可看代打後接守。沒有可比較人選時，畫面補充可查證的原因。新的快比卡直接顯示前兩位候選間的差距，單位為百分點。

## 全季候選名單

沿用原回測 360 場、第六局起 12,075 個決策點，使用當日以前的球員出賽與當場較早打席的上場紀錄。以事後實際登場確認是否納入推估候選；出場以外的人選是否正式可用沒有獨立標籤。

- **換投**：117 筆無候選中，98 筆在開季觀察期缺少符合條件的歷史人選，19 筆推估候選已在場或本場已用過。
- **代打**：120 筆無板凳候選，99 筆缺少歷史人選，21 筆推估候選已在場或本場已用過。另有 1,590 筆有板凳候選、接守條件未確認。
- 21 日版把無換投候選從 117 筆降至 98 筆，實際換投人選納入從 1,962／2,228 提升到 2,036／2,228，候選中位數由 7 人升到 9 人。35 日版再提高納入率，空名單仍為 98 筆。
- 季初備援只在開季 10 天的空名單使用前一季本隊最後 21 天出賽紀錄。換投空名單降至 19 筆、代打空名單降至 0 筆。由於休季隊籍異動缺少即時登錄，正式名單維持原規則。各月份、球隊與候選數分布見 [候選報告](candidates.json)。

## 代打後接守

2026 全季 561 次代打，從 Rebas 下一個守備半局的逐打席陣容還原。

| 分類 | 次數 |
|---|---:|
| 代打球員在下一守備半局出現在守備陣容 | 240 |
| 下一守備半局由其他球員開場守備 | 163 |
| 這次代打後沒有下一個守備半局 | 156 |
| 紀錄無法確認代打者與接守 | 2 |

240 筆包含開場已確認的 238 筆，以及在同半局後續打席補查的 2 筆。其他球員開場守備的 163 筆中，有 116 筆能核對原打者的守位及該守位下一半局開場的人選。僅在前後陣容與球員識別均確認時顯示姓名。八個已公開日期可見 **37 筆接守紀錄**、**223 個帶有候選排除原因的打席**。接守與候選排除使用各日期的補充檔，原模型輸出與賽前資訊可獨立驗證。[守位統計](fielding.json)

## 排序敏感度

用八日既有分數固定同一打席、候選和日期截止，對照階層式、樹模型及移除個別分項。1,443 組代打評估中，移除階層式左右優勢對混合分數的貢獻，改變首選 176 次、跨提示門檻 10 次。1,725 組換投評估中，去除疲勞項不改變牛棚首選，27 次改變是否跨過 1 個百分點門檻。另按晚局近比分及樣本數分組。此分析衡量排序及提示的敏感度，正式模型採用仍依新賽季的未見樣本與[既定預測誤差及校準指標](../model-horizons-20261113/README.md)判斷。[排序診斷](ranking.json)

## 下個球季的增量進件演練

取 2024 與 2025 的 9/20 起末段資料作基底，用 2026/03/29–04/05 的 16 場初始化，再加入 2026/04/06–04/12 的 13 場。再次送入同批 13 場取得相同資料 ID。用同一場原檔增加換行模擬來源修訂；未接受時被拒絕，明確接受後只更新該場來源雜湊。四輪進件均使用來源球員 ID 驗證打席與逐球身分。[進件收據](intake.json)

## 重現方式

先依 [2026 換投回測](../timing-2026/README.md)準備同版的三季原始資料、2026 設定與逐打席 CSV。從專案根目錄執行以下指令，每輪指定新的本機暫存路徑。

```text
python scripts/audit_candidate_coverage_2026.py --timing-csv <timing_backtest.csv> --out <candidate-report.json>
python scripts/audit_2026_fielding_coverage.py <raw-data/rebas/2026> --out <fielding-report.json>
python scripts/export_replay_evidence_2026.py --source docs/data/replay --fielding <fielding-report.json> --coverage <candidate-report.json> --out <staging-directory>
python scripts/audit_replay_ranking_stability.py --source docs/data/replay --out <ranking-report.json>
```

匯出後核對日期批次、完整打席索引及實際代打標籤，確認後發布日期清單與各日補充檔。增量進件用 `scripts/stage_season_update.py` 搭配前述三個日期範圍及既有資料進件收據的量測例外。以 [CI 與瀏覽器驗收指令](../../ci-validation.md)測試正式匯出。

## 驗收

- 重複匯出日期索引與八份補充檔，逐檔位元組一致。發布包 2,959 份資產，新增八份補充檔，更新日期索引與 HTML、CSS、JavaScript，既有模型資料與打席分數的雜湊一致。
- 233 項 JavaScript 測試通過。177 項完整 Python 測試中 174 項通過，3 項舊版專用案例因缺少舊匯出檔跳過。
- Edge 靜態站測 320、390、768、1280 CSS px，另做 125% 版面縮放。WebKit 測 390、1280 CSS px，本機 Python API 以 Edge 390 CSS px 重跑。覆蓋情境連結、接守與候選排除、鍵盤展開、HTTP 503 重試、回放切換、牛棚 A／B、逐次復原與名單備份。
- 瀏覽器上一頁與下一頁會還原逐打席的攻守視角、日期清單原本的子頁及一般使用者或球隊入口。代表案例可在頁內開啟。跳到「比較球員」時保留已渲染的結果與揭示狀態。
- 驗收牛棚 A／B 時，先計算兩個方案，再連續換投與逐次復原。名單變更會隱藏舊投手列並清除舊容量結果，回到原配置後可以沿用當時的容量與順位。全選與換隊時都要核對已退場與不可用球員不會進入新方案。
