## 簡報在講什麼

比賽關鍵時刻該不該代打、換投？簡報依「問題 → 方法 → 網站 → 後續」四章說明我們如何在同一個局勢下比較人選，回答「差多少、誰接守、憑什麼」。

| 官方初審要求 | 頁面 | 內容 |
|---|---|---|
| 希望解決的棒球問題 | 4、6 | 同一關鍵局勢下的代打／換投人選比較 |
| 目標使用者與情境 | 5、7 | 一般使用者與球隊兩種模式，加上獨立的單日分析 |
| 使用資料 | 9 | Rebas 逐球資料、歷年守位、CPBL 球員資料與時間界線 |
| 分析方法 | 10–14 | 部分池化與梯度提升樹集成、勝率換算、時間順序檢驗、換投時機回測 |
| 產品構想 | 16–26 | 實際網站操作：選入口、設定局勢、選人、判讀結果、單日回放 |
| 預期成果與開發規劃 | 12、28–30 | 目前成果的限制，以及跨年資料、長短期權重、多局牛棚三項後續工作 |

## 讀數字時請注意

- **+0.040 分**（第 14 頁）：系統提示換投、但教練讓投手續投時，進攻方 RE24 較高。這是觀察到的差異，**不代表換投就能改善結果**。
- **11,868 個**（第 13 頁）：2025 年第 6 局起可評估的換投決策點數量。
- **452 組**、**226 打席**：分別是網站與 Python 重算對照一致的攻守比較數，以及單日回放收錄的打席數，**都不是準確率**。
- 第 28 頁區分已完成的 2024–2025 身份串接與尚未接入的 2026 資料；第 29–30 頁的近期權重及多局牛棚仍為後續研究。
